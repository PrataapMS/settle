Settle · for the tech-stack review

Decision state: one log, one state, per decision

The log is authoritative and append-only. The state is the latest decision record, rebuilt from the log at any time and sent to the model each turn. Because the state is derivable, it needs no signature. That makes it simpler than the current token and more complete.

Rules

  1. A decision turn appends to the log and replaces the state with v+1. Nothing else writes the state.
  2. A meta turn, or a message the turn check marks too vague or off topic, appends to the log only. It may read the state but never change it.
  3. Rewinding to vN rebuilds the state from the log up to vN; later entries stay in the log, marked superseded.
  4. Import replays the log through the engine and compares every hash. Any mismatch stops the import and names the first bad entry.
  5. Predictions come due at check_at; the thread shows a prompt to grade them. Only you grade.
  6. Export is one JSON file: state, log and settings. Markdown export is for reading, not restoring.

When signing would earn its place

Only when a server must trust state the client holds, such as shared read-only links or a hosted engine. The key then stays server-side. For local-only, no-login use, a signature adds code without protecting anything.
